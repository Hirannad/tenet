# Retro

Append-only, newest entry on top. **Not a log of the notes — a log of the process.**

An entry goes here when **a rule only held because someone enforced it by hand.** Two sources:

- **A vault rule did not catch something.** A note came back `unclear` or was rejected on form, a
  convention was broken, a required property was missing, or a written rule had no mechanism
  behind it.
- **You had to say it.** Any rule — the global `CLAUDE.md`, a repository convention, something you
  had already stated — that held only because you pointed it out.

What does **not** belong here: rejecting a note on its merits, or changing your mind. That is
normal operation, not a deviation.

An entry says four things: **what deviated, which rule it touched, which error class it falls in,
and what would have caught it.** The class matters because the same mistake can surface on two
different rules, and counting per rule then hides the repetition.

**If the same rule or the same class appears twice, that is not chance** — `tenet-sweep`'s
repeat-offender check looks for exactly this. From there, two paths, never a third: the rule
**gets a mechanism that fails** when it is broken, or the rule **is deleted**. Writing it down
again, in bold, is the third path — the one that grows the rule list while compliance falls.

## Error classes

Start with none. Add a class the first time a deviation does not fit an existing one; the list may
grow, but the meaning of an existing class must not drift.
